# 3-2 MID360 雷达坐标配置与数据采集

环境：Ubuntu 22.04 + ROS 2 Humble。本文命令均在机器狗的 Ubuntu 终端执行。

## 实验原理

### 1. 安装外参与 TF

雷达测出的点位于雷达坐标系 `lidar_link` 中。要把点转换到机身坐标系 `base_link`，需要知道雷达相对机身的位置和旋转，这组参数叫“安装外参”，通过 TF 发布坐标关系。

- 位置用 `[x,y,z]` 表示，单位米，按实际 `base_link` 的右手坐标系测量。
- 启动参数中的角度用 `[roll,pitch,yaw]` 表示，分别为滚转、俯仰、偏航，单位弧度。
- 参数文件中的旋转用四元数 `[x,y,z,w]` 表示。这里的 `x、y、z` 是旋转的向量部分，`w` 是标量部分，不是高度。绕单位轴旋转 θ 时，`w=cos(θ/2)`。

程序用欧氏距离比较位置，用归一化四元数的绝对内积计算旋转角误差 `2*acos(abs(dot))`。四元数 `q` 与 `-q` 表示相同旋转，不能逐项相减。

**TF 存在、配置一致，不代表安装已标定准确。** `matches_expected=true` 只说明 TF 与填写的参考值一致，还需要独立测量记录。

### 2. 录包与回放

rosbag2 保存消息及时间信息。回放是重新发布保存的数据，不是重新采样。本章记录：

| 话题 | 内容 |
| --- | --- |
| `/livox/lidar` | 原始 CustomMsg，含逐点时间信息 |
| `/course/points_raw` | 课程点云 |
| `/course/imu` | 已换算为 SI 单位的 IMU |
| `/tf`、`/tf_static` | 动态、静态坐标变换 |

真机录制不需要 `/clock`。离线回放由播放器生成唯一的 `/clock`，检查节点使用仿真时间；不重复发布包内录入的时钟，也不同时运行第二个时钟源。静态 TF 使用能让晚加入订阅者收到数据的 QoS。

### 3. 有界录制

真机模式要求点云、IMU 接收年龄小于 1 秒，所需 TF 可用，连续就绪约 2 秒后开始录制。就绪检查只决定能否开始，不代表采样时间或标定已验证通过。

默认录制最多 30 秒实际经过时间、单缓冲区 16 MiB。程序限制时长为 1～30 秒、单缓冲区为 1～64 MiB；双缓冲和其他组件会占用额外内存。默认磁盘停止阈值为 512 MiB，每 0.5 秒检查，文件可能因缓存和检查间隔略超过阈值。

启动和订阅建立会占用时间，所以请求 30 秒时，包内有效数据可能约为 27～29 秒，应结合消息数和校验结果判断。结束录包时程序发送 SIGINT，等待保存 `metadata.yaml` 和索引。

本章按真机流程操作；原文的仿真兼容说明不作为本次真机验收依据。

## 实验目标

1. 理解安装外参，区分“TF 存在”“配置一致”和“实际测量准确”。
2. 独立完成三次静态采集，分别保留资源有界、索引完整的原始数据。
3. 检查录制时长、点云与 IMU 消息数、TF 和索引。
4. 分别回放三份数据，检查消息和坐标关系，正确管理唯一时钟。
5. 掌握参数保存、自动编号和本次常见报错的处理。

### 3. 准备参考参数文件（首次设置或安装变化后执行）

优先沿用已正常录制的参数文件。以下命令先加载已有设置；没有有效路径时，才使用固定路径准备一份文件，不覆盖已有文件。

```bash
source ~/catkin_ws_lite3dog/course_env.sh
if [ -f "$HOME/catkin_ws_lite3dog/mid360_env.sh" ]; then
  source "$HOME/catkin_ws_lite3dog/mid360_env.sh"
fi

export LIDAR_XYZ='[0.210,0,0.161308]'
export LIDAR_RPY='[0,0.338594,0]'
export BODY_HEIGHT='0.325504965'

mkdir -p "$HOME/catkin_ws_lite3dog/real_configs"
if [ -z "$FRAMES_CFG" ] || [ ! -f "$FRAMES_CFG" ]; then
  export FRAMES_CFG="$HOME/catkin_ws_lite3dog/real_configs/lab3_2_frames.yaml"
  if [ ! -e "$FRAMES_CFG" ]; then
    cp "$(ros2 pkg prefix --share lite3_lab_3_2)/config/params.yaml" "$FRAMES_CFG"
  fi
fi

echo "本次参数文件：$FRAMES_CFG"
vi "$FRAMES_CFG"
```

在原有 YAML 结构中修改这两项，保留原有缩进和其他字段：

```yaml
lidar_translation_m: [0.210, 0, 0.161308]
lidar_quaternion_xyzw: [0, 0.168489441, 0, 0.985703459]
```

保留默认 `duration_s=30` 和缓存、磁盘限制。vi 操作：按 `i` 编辑，改完按 `Esc`，输入 `:wq` 并回车保存。

以后角度改变，用下面命令重新换算四元数，再更新 YAML：

```bash
python3 -c 'import os,yaml; from lite3_course_common.geometry import rpy_quaternion; print(rpy_quaternion(yaml.safe_load(os.environ["LIDAR_RPY"])).tolist())'
```

启动参数和 YAML 参考值使用同一组测量结果。该 YAML 只用于比较，不修改实际安装 TF；雷达驱动 JSON 外参保持零。

### 4. 永久保存参数（设置一次即可）

关闭终端会丢失临时变量，但不会删除已保存的 YAML 或数据包。先确认路径有效：

```bash
echo "$FRAMES_CFG"
test -f "$FRAMES_CFG" && echo "参数文件存在，可以继续"
```

看到“参数文件存在，可以继续”后执行，保存四个变量，并设置新终端自动加载：

```bash
cat > ~/catkin_ws_lite3dog/mid360_env.sh <<EOF
export LIDAR_XYZ='[0.210,0,0.161308]'
export LIDAR_RPY='[0,0.338594,0]'
export BODY_HEIGHT='0.325504965'
export FRAMES_CFG='$FRAMES_CFG'
EOF

line='source "$HOME/catkin_ws_lite3dog/mid360_env.sh"'
grep -qxF "$line" ~/.bashrc || echo "$line" >> ~/.bashrc
source ~/catkin_ws_lite3dog/mid360_env.sh
```

检查四项都不为空，且参数文件路径正确：

```bash
echo "雷达位置：$LIDAR_XYZ"
echo "雷达角度：$LIDAR_RPY"
echo "机身高度：$BODY_HEIGHT"
echo "参数文件：$FRAMES_CFG"
```

以后修改永久设置：

```bash
vi ~/catkin_ws_lite3dog/mid360_env.sh
source ~/catkin_ws_lite3dog/mid360_env.sh
```

修改安装位置、角度后，同时更新 YAML 中的参考值。

### 5. 录制：每录一次自动换下一个 run

先按 `Ctrl+C` 完整退出上一轮录制或回放。每次复制下面整段，会自动选择未使用的 `run1、run2、run3…`，跳过已有目录：

```bash
source ~/catkin_ws_lite3dog/course_env.sh
source ~/catkin_ws_lite3dog/mid360_env.sh

BASE="$HOME/catkin_ws_lite3dog/results/lab_3_2"
n=1
while [ -e "$BASE/run$n" ] || [ -L "$BASE/run$n" ]; do
  n=$((n + 1))
done
RESULT_DIR="$BASE/run$n"
echo "本次保存位置：$RESULT_DIR"

if [ -n "$LIDAR_XYZ" ] && [ -n "$LIDAR_RPY" ] && [ -n "$BODY_HEIGHT" ] && [ -f "$FRAMES_CFG" ]; then
  ros2 launch lite3_lab_3_2 experiment.launch.py \
    mode:=real native_execute:=false autostart:=true rviz:=true \
    lidar_xyz:="$LIDAR_XYZ" \
    lidar_rpy:="$LIDAR_RPY" \
    initial_body_height:="$BODY_HEIGHT" \
    params_file:="$FRAMES_CFG" \
    result_dir:="$RESULT_DIR"
else
  echo "参数为空或参数文件不存在，请先完成第 3、4 步。"
fi
```

每次操作顺序：

1. 等待出现“已启动有界录包”。驱动启动成功不等于已开始录制。
2. 从录包开始等待约 30 秒，让录制器自动保存。
3. 按 `Ctrl+C` 退出整个 launch，等待返回命令提示符。
4. 按下一步检查，通过后算一次有效采集，再重复整段录制命令。

录制结束后，驱动、RViz 和 launch 可能仍在运行，不能直接在另一个终端重复启动。失败目录也保留，编号有跳号不影响有效次数。

`autostart:=true` 启动录包；`native_execute:=false` 保持不启用运动。已有本体 URDF 或外部程序发布传感器安装 TF 时，追加 `publish_sensor_tf:=false`，避免重复发布。

只有确认已有的是同一真机模式、配置正确的公共运行时，才考虑用 `start_runtime:=false` 复用。从离线回放切到真机录制，先退出回放。

### 6. 检查本次录制

退出后在同一个终端执行，`RESULT_DIR` 仍指向本次目录：

```bash
cat "$RESULT_DIR/record_result.json"
ros2 bag info "$RESULT_DIR/raw_bag"
cat "$RESULT_DIR/frames.json"
```

重点看：

- `valid_recording: true`、`returncode: 0`、`metadata_exists: true`。
- `validation_errors` 为 `[]`，`bag_duration_s` 大于 0。
- `/livox/lidar`、`/course/points_raw`、`/course/imu` 消息数均大于 0，TF 话题也已保存。
- `frames.json` 中所需 TF 可用，参考比较符合预期。`matches_expected=false` 时核对配置、坐标方向与容差。

**有效录制不代表回放、SLAM 或独立标定已通过。**

### 7. 用命令统计有效录制次数

复制整段，包括开头的 `python3 - <<'PY'` 和末尾单独一行的 `PY`：

```bash
python3 - <<'PY'
import json
from pathlib import Path

root = Path.home() / "catkin_ws_lite3dog/results/lab_3_2"
count = 0
for file in sorted(root.glob("*/record_result.json")):
    try:
        data = json.loads(file.read_text())
    except (ValueError, OSError):
        print(f"无法读取：{file.parent.name}")
        continue
    bag_exists = (file.parent / "raw_bag/metadata.yaml").is_file()
    if data.get("valid_recording") is True and bag_exists:
        count += 1
        duration = data.get("bag_duration_s", 0)
        print(f"有效录制：{file.parent.name}  时长 {duration:.2f} 秒")
print(f"\n有效录制共 {count} 次，目标 3 次，还需 {max(0, 3-count)} 次。")
PY
```

这里只统计有有效录制结果和索引的目录，回放目录不计入。三次必须独立采集，不能复制一份 bag 充当多次采集。

### 8. 分别回放三份数据

先退出真实采集，确认真实驱动已停止。选择一份有效录制，下面以 `run1` 为例；回放目录自动加时间，避免重名：

```bash
source ~/catkin_ws_lite3dog/course_env.sh
RESULT_DIR="$HOME/catkin_ws_lite3dog/results/lab_3_2/run1"
REPLAY_DIR="${RESULT_DIR}_replay_$(date +%Y%m%d_%H%M%S)"

if [ -f "$RESULT_DIR/raw_bag/metadata.yaml" ]; then
  ros2 launch lite3_lab_3_2 experiment.launch.py \
    mode:=bag bag_source:=real rviz:=true \
    bag_path:="$RESULT_DIR/raw_bag" \
    playback_rate:=0.5 \
    result_dir:="$REPLAY_DIR"
else
  echo "未找到数据包索引，请检查 RESULT_DIR。"
fi
```

检查并记录：

- 日志以 `READ_ONLY` 打开数据库，倍率为 `0.5`。
- RViz 能看到点云，`Global Status`、`Raw points` 为 `Ok`，没有 TF 错误。
- 消息能够输出，坐标关系合理。需要核查时，在播放期间另开同域终端执行：

```bash
source ~/catkin_ws_lite3dog/course_env.sh
ros2 topic echo /course/imu --once
ros2 topic info /clock -v
```

**播完仍要回到启动回放的终端按 `Ctrl+C`，等整个程序退出。** 把 `RESULT_DIR` 改为下一份实际目录，再重复回放。回放时不同时启动真实驱动、仿真程序或第二个播放器。

## 本次遇到的问题与解决方法

### 1. `lidar_xyz必须为3个有限数`

通常是换终端后变量为空或格式错误。加载永久设置，再检查四项：

```bash
source ~/catkin_ws_lite3dog/mid360_env.sh
echo "$LIDAR_XYZ"
echo "$LIDAR_RPY"
echo "$BODY_HEIGHT"
echo "$FRAMES_CFG"
```

当前位置应为 `[0.210,0,0.161308]`。有误时编辑 `mid360_env.sh` 并重新加载。只改 YAML，不会给启动命令里的变量赋值。

### 2. 常见提示与检查失败

| 提示或问题 | 含义与处理 |
| --- | --- |
| `Stereo is NOT SUPPORTED` | 不支持立体显示，不影响普通点云 |
| `stdin is not a terminal device. Keyboard handling disabled.` | 播放器快捷键不可用，不影响自动播放 |
| `Opened database ... READ_ONLY` | 数据库已打开，仍需看 RViz 确认显示 |
| 点云正常显示，但录制报错 | 显示和录制是两件事，以录制结果文件为准 |
| 播完后点云停住 | 单次回放结束，按 `Ctrl+C` 退出整个程序 |
| 请求 30 秒，数据约 27～29 秒 | 启动和订阅建立占用部分时间，结合消息数与校验结果判断 |
|                                                              |                                                        |
| `matches_expected=false` | 核对位置、四元数、坐标方向、容差和重复 TF 发布 |
| `valid_recording=false` | 查看 `validation_errors` 和各话题消息数 |
| `no_pointcloud_messages` | 没录到有效点云，检查驱动后换新目录重录，保留失败记录 |
| 没有 `metadata.yaml` | 查看 `rosbag_record.log`、磁盘空间，确认已等待保存完成 |
| 回放缺少 TF 或有时间错误 | 检查 `/tf_static`、QoS 和是否存在第二个时钟源 |
