## 6. 修正并检查 mesh 引用

官方当前模型使用 `./meshes/xxx.STL`。RViz 经 robot_description 接收 XML 后不能可靠地靠原文件目录定位它们，所以改成包资源 URI。

开发板执行：

```bash
python3 - <<'PY'
from pathlib import Path
import xml.etree.ElementTree as ET
p = Path.home() / 'catkin_ws_lite3dog/src/06_simulationmode_grazebo/6-2_robot_modeling/urdf/Lite3.urdf'
text = p.read_text()
root = ET.fromstring(text)
prefix = 'package://simulationmode_grazebo/6-2_robot_modeling/urdf/meshes/'
changes = {}
for mesh in root.findall('.//mesh'):
    old = mesh.attrib['filename']
    if old.startswith(prefix):
        name = old[len(prefix):]
    elif old.startswith('./meshes/') or old.startswith('meshes/'):
        name = old.split('meshes/', 1)[1]
    else:
        raise SystemExit('出现预期之外的 mesh 路径，请先检查：' + old)
    if not (p.parent / 'meshes' / name).is_file():
        raise SystemExit('缺少 mesh：' + name)
    changes[old] = prefix + name
for old, new in changes.items():
    text = text.replace('filename="' + old + '"', 'filename="' + new + '"')
ET.fromstring(text)
p.write_text(text)
print('模型 XML 与 mesh 文件检查通过，路径已统一。')
print('惯性块数量：', len(root.findall('.//inertial')))
print('碰撞块数量：', len(root.findall('.//collision')))
PY
```

数量非零不代表物理参数全部合格。上游模型包含 MuJoCo 扩展、负值 mesh scale、足部零惯性；Gazebo 的转换与渲染需实际验证。固定足部通常会在 URDF→SDF 时合并到父连杆，若出现惯性或 mesh 警告，应保留日志后针对模型处理，不要随意填写惯性数值。

## 9. Gazebo 模型生成启动文件

创建 `6-1_sim_env_setup/launch/spawn.launch.py`。此 launch 只生成模型，不重复启动世界：

```python
from pathlib import Path
import xml.etree.ElementTree as ET
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    share = Path(get_package_share_directory('simulationmode_grazebo'))
    root = ET.fromstring((share / '6-2_robot_modeling/urdf/Lite3.urdf').read_text())
    # 给 Gazebo 使用安装目录的绝对 file URI，避免 package URI 查找差异。
    prefix = 'package://simulationmode_grazebo/'
    for mesh in root.findall('.//mesh'):
        name = mesh.attrib['filename']
        if name.startswith(prefix):
            path = share / name[len(prefix):]
            if not path.is_file():
                raise RuntimeError('Missing mesh: ' + str(path))
            mesh.set('filename', path.as_uri())
    # MuJoCo 专用标签不传给 Gazebo。
    for element in list(root):
        if element.tag == 'mujoco':
            root.remove(element)
    description = ET.tostring(root, encoding='unicode')
    return LaunchDescription([
        Node(package='ros_gz_sim', executable='create',
             arguments=['-world', 'lite3_world', '-name', 'lite3',
                        '-param', 'robot_description', '-z', '0.65'],
             parameters=[{'robot_description': description}], output='screen'),
    ])
```

先启动世界再生成模型，避免使用固定延时猜测世界是否准备好。

## 13. SSH 无显示与图形问题

纯 SSH 无桌面显示时，可仅运行服务器：

```bash
source ~/env_ros2.sh
SIM_SHARE=$(ros2 pkg prefix --share simulationmode_grazebo)
ign gazebo -s -r -v 4 "$SIM_SHARE/6-1_sim_env_setup/worlds/lite3_empty.sdf"
```

随后在另一个终端执行第 12 节生成步骤。这验证服务器与生成接口，不验证图形画面。`-s` 表示不启动 GUI；有相机传感器时仍可能需要额外渲染支持。

ROS_DOMAIN_ID 相同只是 ROS 通信条件之一，不会把 Gazebo 桌面画面自动传到 Windows。PC RViz 还需要兼容的 ROS 环境、模型资产、TF 与关节状态；视频需要传感器和对应图像桥接。本指南优先用开发板接显示器验证 GUI。

若有桌面但遇到 OpenGL/EGL 错误，可在终端临时尝试软件渲染：

```bash
LIBGL_ALWAYS_SOFTWARE=1 ign gazebo -v 4 "$SIM_SHARE/6-1_sim_env_setup/worlds/lite3_empty.sdf"
```

这不是驱动修复，可能很慢或仍然失败。20T 是 AI 算力指标，不能作为 Gazebo 图形加速兼容性的保证。

## 14. 常见问题与停止点

| 问题 | 下一步 |
| --- | --- |
| `ign` 不存在 | 检查第 2 节 apt 候选与安装结果，不直接改装其他 Gazebo |
| `Package simulationmode_grazebo not found` | 查看编译结果并 source 当前 install/local_setup.bash |
| RViz 空白 | Fixed Frame=TORSO，添加 RobotModel，检查 robot_description 和 GUI 发布的 joint_states |
| mesh 找不到 | 核对大小写、统一 URI、安装 share 中实际文件；新加文件后重新编译 |
| create 服务没有出现 | 检查世界名、UserCommands 插件、服务器日志；两个终端使用相同环境 |
| spawn 超时 | 先确认服务存在，并确认 ros_gz 与 Fortress 匹配 |
| 模型镜像部分渲染错误 | 检查上游负值 mesh scale；需要单独生成镜像网格，不能直接去掉负号 |
| 仿真后倒下 | 尚无关节/步态控制器，先完成模型生成验收 |
| 惯性/转换错误 | 保留具体连杆名与日志，检查 URDF→SDF 固定关节合并情况 |
