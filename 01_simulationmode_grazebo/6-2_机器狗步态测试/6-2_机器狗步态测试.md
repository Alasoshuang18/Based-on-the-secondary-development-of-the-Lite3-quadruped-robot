# 6-3_机器狗步态仿真

本节在已经搭建完成的香橙派 ROS 2 Humble／Gazebo Fortress 环境中，使用原有 Lite3 模型和关节控制器，完成固定机身下四条腿依次抬起、保持、落下的仿真测试。

最终成功方案：**只运行一个 Gazebo 服务器和一个控制器管理器；两个控制器均为 active；ROS 仿真时钟与关节反馈正常；Python 脚本通过 FollowJointTrajectory action 一次提交完整轨迹，等待执行结果后再测试下一条腿。**

本节验收范围是固定机身的单腿动作与 Walk 顺序演示，完成一轮 HL→FL→HR→FR，四腿实际关节反馈经正解计算的相对抬脚峰值均约30.0mm，全部PASS，最后回到参考站姿，尚不包含自由机身前进、后退、转向或动态平衡。固定机身不会向前移动。

### 5.4 已加载控制器的恢复方式

仅对 `unconfigured` 的对应控制器执行配置：

```bash
ros2 control set_controller_state joint_state_broadcaster inactive -c /lite3_sim/controller_manager
```

```bash
ros2 control set_controller_state lite3_leg_controller inactive -c /lite3_sim/controller_manager
```

这里 `inactive` 的作用是将未配置的控制器配置好；不能把已active控制器再设为inactive来“确保配置”。

对已配置为inactive的对应控制器，通过最终实测成功的120秒切换请求激活。保持Gazebo播放，单独执行、等待回复：

```bash
ros2 service call /lite3_sim/controller_manager/switch_controller controller_manager_msgs/srv/SwitchController '{activate_controllers: [joint_state_broadcaster], deactivate_controllers: [], strictness: 2, activate_asap: true, timeout: {sec: 120, nanosec: 0}}'
```

```bash
ros2 service call /lite3_sim/controller_manager/switch_controller controller_manager_msgs/srv/SwitchController '{activate_controllers: [lite3_leg_controller], deactivate_controllers: [], strictness: 2, activate_asap: true, timeout: {sec: 120, nanosec: 0}}'
```

预期回复 `ok=True`。如果命令提示失败，先查实际状态，不立即重复请求，也不马上设回inactive。

激活命令运行时按Ctrl+C只结束客户端，不一定取消manager正在处理的切换；不要在等待过程中叠加配置请求。

## 8. 在Gazebo和日志中验收

### 8.1 观察画面

在B右侧Entity Tree选择 `lite3_control`，将视角拉近到可以看清四个足端的位置。保持播放。参考模型脚端和地面之间的距离观察，而不是只看机身是否移动。

应看到HL、FL、HR、FR依次抬起和落下。机身被固定，不会向前平移。30mm抬脚在全景视角下可能不明显，需要靠近模型观察。

### 8.2 理解数据

数组顺序固定为：

```text
[FL左前, FR右前, HL左后, HR右后]
```

例如HL在最高处：

```text
actual_relative_z_mm=[-0.0, -0.0, 30.0, -0.0]
peak_mm=[0.0, 0.0, 30.0, 0.0]
```

第三项30mm表示左后腿上抬约30mm，其他三腿保持参考高度。四腿依次运动，不应期待四个数同时为30。

`actual_relative_z_mm` 来自实际关节反馈和Lite3正解，是相对参考站姿的机身坐标Z变化；`peak_mm` 是当前完整动作中连续反馈的累计峰值。二者都不是接触力。固定且水平的机身使这个相对高度可用于本次抬脚观察，但不能把它直接称作世界坐标的足底地面间隙。

完整轨迹脚本要求action成功、目标腿实际峰值达到计划高度80%以上、非目标腿没有超过8mm的相对上抬，并且动作末尾实际关节回站姿误差小于0.03rad，才打印该动作PASS。

### 8.3 最终实测记录

| 顺序 | 目标腿 | 实际相对上抬峰值 | 结果 |
| --- | --- | --- | --- |
| 1 | HL 左后 | 约30.0mm | PASS |
| 2 | FL 左前 | 约30.0mm | PASS |
| 3 | HR 右后 | 约30.0mm | PASS |
| 4 | FR 右前 | 约30.0mm | PASS |

非目标腿日志中的少量残余上抬约0.1～0.2mm；四腿依次动作完成并回参考站姿。终端输出COMPLETE，Gazebo中看到实际运动，构成本轮验收结果。

## 9. 本次踩坑与保留的处理方式

| 现象 | 原因或定位结果 | 最终处理 |
| --- | --- | --- |
| `No such file or directory` | 大小写、重复`.py`后缀或使用了板上不存在的新文件名 | 用ls确认，最终保留`Lite3_phase_demo.py` |
| `Another joint-command publisher exists` | 旧lite3_controller仍在后台，关闭窗口没有结束进程 | 查发布者及实际PID，正常停止旧控制程序 |
| manager状态查询前后矛盾，提示“已加载”后又“不存在” | 本次实际发现两个Gazebo服务器、两个同名manager | 结束确认过的旧服务器，manager数量恢复1 |
| spawner失败，但控制器已列为unconfigured | 控制器已经加载，尚未配置，或请求结果与当时实际状态不一致 | 按当前状态配置与激活，不重复加载 |
| 激活提示失败，再激活却提示已active | 服务返回与实际切换状态不一致 | 先查实际状态，active就保留，不再切到inactive |
| `Switch controller timed out after 5 seconds` | 切换未在等待时间内完成；仿真暂停会阻止更新循环推进 | 确认播放、时间推进，再用120秒请求等待切换 |
| 输入命令后只显示`>` | YAML字符串末尾引号未闭合，命令尚未执行 | 使用成对单引号的一整行请求 |
| 配置服务连续超时 | 之前的切换可能仍在等待，重复请求不能解决 | 保持播放、等待处理结束，再查实际状态 |
| `No joint feedback or /clock` | 本次关节反馈有消息，ROS时钟没有数据 | 分别检查两路数据，恢复现有clock桥接 |
| `/clock`出现在列表但echo无消息 | 话题存在不代表正在供数 | 必须验证实际收到时钟且时间增加 |
| `/model/lite3_control/pose`在ROS里Unknown | 它是Gazebo话题，桥接后ROS名称为`/lite3_sim/model_pose` | 分清两侧话题；完整轨迹测试不依赖位姿测量工具 |
| H的`model_seen=False` | H未收到符合要求的模型位姿，不能计算同步离地距离 | 不拿无同步数据判断抬脚，当前实验用实际关节正解与画面 |
| phase和swing不断变化，画面几乎不动 | 旧短轨迹程序实测实际高度仅约0～2.4mm，计划变化不等于动作完成 | 改用最终完整action轨迹，四腿实测约30mm |
| 旧程序显示Complete但没有明显抬脚 | 旧结束检查只确认末尾接近站姿，没有验收抬脚峰值 | 最终版本要求每腿实际峰值和action结果通过 |
| controller_state里存在error字段 | error是参考值与反馈值之差，不是异常日志 | 本次单次站姿误差约10⁻¹²rad，可视为零 |
| effort全是.nan | 没有有效力矩测量 | 本次位置控制不使用该字段验收 |

旧短轨迹程序的问题定位依据是：单次2秒回站姿能执行，连续100ms未来端点实测抬脚不足，而完整action轨迹达到30mm。具体短轨迹内部时序原因没有单独完成板上验证，因此本节保留已经实际通过的完整轨迹路径，不继续混用旧方案。

原ROS Noetic／Gazebo Classic／Collie教学文档只参考“固定机身观察步态相位”的方法，不复制其关节名、全零站姿、坐标方向、12个Float64控制器或安装步骤。Lite3继续使用自身几何和现有ROS 2接口。

```bash
(
  count=$(ros2 node list --no-daemon | grep -xc '/lite3_sim/controller_manager')
  [ "$count" = 1 ] || { echo "manager数量=$count，先修复为1个"; exit 1; }
  for c in joint_state_broadcaster lite3_leg_controller; do
    listing=$(ros2 control list_controllers -c /lite3_sim/controller_manager) || exit 1
    state=$(printf '%s\n' "$listing" | awk -v c="$c" '$1==c {print $NF}')
    if [ "$state" = unconfigured ]; then
      ros2 control set_controller_state "$c" inactive -c /lite3_sim/controller_manager || exit 1
      state=inactive
    fi
    case "$state" in
      active) echo "$c 已active，保留" ;;
      inactive)
        ros2 service call /lite3_sim/controller_manager/switch_controller \
          controller_manager_msgs/srv/SwitchController \
          "{activate_controllers: [$c], deactivate_controllers: [], strictness: 2, activate_asap: true, timeout: {sec: 120, nanosec: 0}}" || exit 1 ;;
      '')
        ros2 run controller_manager spawner "$c" -c /lite3_sim/controller_manager \
          --controller-manager-timeout 60 --switch-timeout 120 --service-call-timeout 150 || exit 1 ;;
      *) echo "$c 当前状态=$state，停止本段检查"; exit 1 ;;
    esac
  done
  ros2 control list_controllers -c /lite3_sim/controller_manager
)
```
